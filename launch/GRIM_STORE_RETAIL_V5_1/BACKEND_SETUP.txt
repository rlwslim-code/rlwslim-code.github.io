WORKFLOW
1. Customer signs in; checkout reads the same Supabase customer and wallet.
2. Configured measured zone rates appear as delivery choices, including a
   configured zero-fee rate. The signed choice binds customer, address, products,
   prices and rate, expires after ten minutes, and is checked again before payment.
3. Without a configured rate, customer requests a delivery quote. Admin confirms
   the fee; each approved, unexpired quote can start its own payment automatically.
4. Card and bank transfer open Paystack with the server-calculated total. A
   callback or signed webhook triggers server verification of reference, amount,
   currency, customer, environment and selected channel.
5. Wallet checkout uses the existing atomic wallet debit inside the same database
   transaction as the order and receipt. A failure rolls everything back.
6. Retries reuse the stored reference. Duplicate callbacks do not create another
   order or debit. Paid money with an order-recording failure stays recoverable.
7. Saved billing uses the existing protected address store. Partial profile or
   address failures no longer hide wallet and payment recovery results.

SCOPE
Preserves the uploaded customer/auth, admin, products, support, appearance,
address autocomplete and wallet modules. This release integrates backend payment,
order, delivery and billing paths; it does not rebuild the website or mobile app.
Existing email delivery still needs valid RESEND_API_KEY and
TWO_FACTOR_FROM_EMAIL (verified sender). It cannot repair provider settings from
an offline ZIP. Checkout settlement is recorded in orders/receipts; this release
does not add a new transactional email worker or automatic courier booking.
Live checkout and wallet funding remain NGN. Existing other-currency wallets are
preserved; this release does not invent exchange rates or currency conversion.

ROLLBACK
Retain the current backend files before replacing them. Pause new ordering with
GRIM_CHECKOUT2_ACCEPT_NEW_ORDERS=false; keep recovery routes and webhook available
for existing payments. Restore prior source if needed. Do not delete attempts,
receipts, customer records or ledger entries when rolling back.
